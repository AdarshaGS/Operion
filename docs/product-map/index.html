Operion Product Map

Where every screen lives, what it is for, who can open it, and how work moves between modules. Click Open module on any module to see every tab and sub-page inside it, with screenshots.

1The four apps

Operion is one web app with four separate areas. Each person lands in exactly one of them after login.

Public pages

/welcome · /login · /apply/:orgSlug

No login. Marketing page, login, online admission form, careers, password reset, invite claim, certificate verification.

School admin app

/dashboard · /students · …

Staff with any non-portal role, and the school Owner. Full sidebar with three groups plus Settings.

Portal

/portal/**

Guardians and teachers whose roles are all marked "portal". Small shell, no sidebar.

Platform admin

/platform/**

You, running the SaaS. Separate login and token. Sees every school.

How admin vs portal is picked: GET /api/v1/me checks the caller's roles. An Owner or any non-portal role gets the admin app; if every role is a portal role, the user gets the portal.

2Sidebar at a glance

The admin sidebar as a user sees it. An item disappears if the user lacks its view permission, or if the platform owner switched that module off for the school. Click an item to open that module.

3Module by module

One entry per sidebar item. "Needs first" lists what must exist before the module is useful.

4Settings map

/settings is a grid of cards; each opens /settings/<section>. Open Settings for a screenshot of every card and the setup wizard.

5How things flow

The main journeys, step by step, with the screen where each step happens.

6Portals

Students do not log in. A guardian acts for each linked child.

7Platform admin

Log in at /platform/login. This area is separate from every school.
